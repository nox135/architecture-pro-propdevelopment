Биометрические данные своих клиентов решено хранить в защищенном хранилище ЦОД в отдельном сегменте сети.
Добавлен аудит-сервис для фиксации всех действий, связанных с биометрическими данными.
Архитектура построена таким образом, чтобы минимально полагаться на безопасность стороннего сервиса (умного дома).
Любое взаимодействие между контурами должно шифроваться и логироваться, включая переходы во внутренней инфраструктуре (из группы сервисов для собственников в защищенный биометрический контур)

Ниже приведены требования, необходимые для реализации внешней интеграции со стороны интегрируемого сервиса и сервиса, который интегрируем:

| №   | Требование | Комментарий |
| --- | ------ | ------------ |
| 1 | Шифрование данных при передаче | TLS 1.2+ с mTLS |
| 2 | Шифрование данных в payload | AES-256 |
| 3 | "Умный дом" должен быть сертифицирован по ISO 27001/ФЗ-152 | Предоставление действующего сертификата от независимого аккредитованого органа |
| 4 | Аутентификация: mTLS + JWT Bearer токен с шифрованной RSA-подписью | ключ-2048 бит, время жизни не более 15 минут, наличие блеклиста, сертификаты в KMS |
| 5 | В payload необходимо наличие correlationId | Для отслеживания в случае неполадок |
| 6 | Необходим четкий перечень возможных ошибок со стороны интегрируемой службы | |
| 7 | Необходима фиксация в SLA пункта о немедленном оповещении в случае проблем безопасности на стороне иынтегрируемой службы | |
| 8 | Хранение ключей в защищенном хранилище KMS/HSM | KMS более вероятно, в случае умного дома |
| 9 | Ротация ключей шифрования каждые 90 дней | Необходимо согласовать механизмы синхронной замены ключа, вероятно, через доступ к общему KMS |
| 10 | Предусмотреть механизмы поддержания целостности данных через hmac | x-signature: b64 hmac-sha256 от канонической строки (x-* заголовки) |
